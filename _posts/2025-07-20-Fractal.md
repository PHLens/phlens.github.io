# Fractal: Joint Multi-Level Sparse Pattern Tuning of Accuracy and Performance for DNN Pruning
## Summary
### What's the problem?
Model pruning eliminates the redundant model parameters while may have no speedup due to the irregular *sparse element access* and *decoding overhead*.

Previous work have proposed a *sparse pattern* to group non-zero elements to form local structures which can enhance memory locality. 

But this often accompanies with handcrafted operator libraries such as cuSparse.

And this kind of sparse pattern often has single-level tiling strategy which is not making the best use of sparsity benefits.

### Related work
- [[TACO]] for static sparse tensors
- [[SparseTIR]] requires carefully designed schedules.

### How does this paper sovled it?
- A loop-based IR called PatternIR for multi-level sparse pattern generation.
- A auto-tuning system for multi-level sparse pattern which make trade-offs between accuracy and speedup.

## Strengths
**Code generation**
- Multi-level Sparse Format: Fractal-[[稀疏矩阵存储格式#ELL|ELL]]
- PatternIR lowering by [[SparseTIR]].
- Adopt [[MetaSchedule]] for operator tuning.
**PatternIR Search space Generation**
- Generating sparse pattern from dense operator expression:
	- Loop tiling
	- Perforation for sparsity
**Make trade-offs between accuracy and latency in tuning process**
- A *greedy search solution* for multi-level patternIR tuning.
- Apply *importance score threshold* for patternIR tuning to maintain accuracy.
- A bidirectional [[LSTM]] *cost model* to predict performance of sparse pattern for both latency tuning and accelerating tuning process.

## Weakness
- Cost model is specified for each backend, and requires extra profiling and training when extended to new hardware.
- ELL format compute efficiency?
- Mainly focus on structured sparsity(sparse pattern is generated from dense expression), how about unstructured sparsity?
- How about data reuse pattern?
